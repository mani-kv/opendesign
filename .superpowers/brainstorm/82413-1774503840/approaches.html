P0: Figma → Wireframe Canvas Pipeline

Three approaches to building the import pipeline and wireframe sketchpad

A

Canvas-First: Extend Rust/WASM Canvas

Add wireframe primitives (section, button, text, image, list, nav) directly to canvas-core in Rust. Figma data maps into these Rust node types. All interaction (draw, select, drag, resize) happens in the WASM canvas.

Pros

  • GPU-accelerated — handles hundreds of wireframe nodes smoothly
  • Your Rust canvas becomes the proprietary moat
  • Single rendering surface — no split between canvas systems
  • Snapshot/persistence already exists, just needs extending

Cons

  • Rust development is slower — each new wireframe type requires Rust + WASM rebuild
  • Text rendering in Vello is non-trivial (font loading, shaping)
  • Harder to iterate on visual design of wireframe components
  • Current canvas only renders filled rectangles — significant work needed
B

Web-First: SVG/HTML Wireframe Canvas

Build the wireframe canvas as a SolidJS SVG/HTML layer (extending the existing agent-sandbox SVG canvas). Wireframe components are SolidJS components. Figma data maps into a TypeScript scene graph. The Rust canvas is used only for visual diff overlays later.

Pros

  • Fast iteration — wireframe components are just SolidJS + CSS
  • Text rendering is free (browser handles it)
  • Builds on existing SVG canvas code (agent-sandbox/canvas.tsx)
  • Design system palette UI is natural in the web layer
  • Drag-and-drop from palette → canvas is straightforward

Cons

  • SVG performance degrades at 500+ nodes (fine for wireframes though)
  • Two canvas systems remain (SVG wireframe + Rust for future rendering)
  • Less "proprietary" — SVG canvas is commodity tech
C

Hybrid: Web Wireframes + Rust Preview

Wireframe editing in SolidJS/SVG (fast iteration). When a Figma design is imported, show a rasterized preview image on the Rust canvas alongside the SVG wireframe decomposition. The Rust canvas handles the preview image layer; the SVG layer handles wireframe manipulation.

Pros

  • Best of both worlds — fast wireframe iteration + GPU preview rendering
  • Figma import shows real design as reference while wireframe is editable
  • Uses each canvas for what it's good at
  • Rust canvas gains image rendering (useful long-term)

Cons

  • Two rendering surfaces to coordinate (z-ordering, pan/zoom sync)
  • More complexity to maintain
  • May feel disjointed if not carefully integrated

⭐ Recommendation: Option B (Web-First)

For an MVP wireframe sketchpad, the web layer wins on iteration speed. Wireframe components are just SolidJS components — you can design, tweak, and add new ones in minutes, not hours of Rust compilation. The existing SVG canvas already has pan/zoom/drag/selection. Text rendering is free. The design system palette is a natural web UI element.

The Rust canvas isn't wasted — it becomes the foundation for visual diff rendering later (P1), where GPU acceleration actually matters. And you can always migrate wireframe rendering to Rust later if SVG becomes a bottleneck (it won't for wireframes).

Database Schema: Ideal vs Existing

Designing from scratch for the agentic prototyping studio, then comparing

Ideal Schema — Designed from Spec

Entity Relationship Overview
PRODUCT
id TEXT PK
name TEXT
directory TEXT UNIQUE
git_root TEXT
created_at INTEGER
updated_at INTEGER
One per mono repo. Root entity.
DESIGN_SYSTEM
id TEXT PK
name TEXT
figma_file_key TEXT
figma_file_name TEXT
tokens TEXT (JSON)
components TEXT (JSON)
styles TEXT (JSON)
last_synced_at INTEGER
created_at INTEGER
updated_at INTEGER
First-class entity. Shared across products.
PRODUCT_DESIGN_SYSTEM
product_id TEXT → PRODUCT
design_system_id TEXT → DS
PRIMARY KEY (product_id, ds_id)
Many-to-many join table.
FEATURE
id TEXT PK
product_id TEXT → PRODUCT
name TEXT
branch TEXT
status TEXT (active|completed|archived)
figma_url TEXT
canvas_state TEXT (JSON)
created_at INTEGER
updated_at INTEGER
Exploration context within a product.
ANNOTATION
id TEXT PK
feature_id TEXT → FEATURE
component_node_id TEXT
component_name TEXT
prompt TEXT
ds_slider REAL (0.0–1.0)
variation_count INTEGER
enrichments TEXT (JSON)
position_x REAL
position_y REAL
created_at INTEGER
User selects component → creates annotation → spawns agent.
AGENT
id TEXT PK
feature_id TEXT → FEATURE
annotation_id TEXT → ANNOTATION
branch TEXT
status TEXT (working|waiting|done)
color TEXT
created_at INTEGER
updated_at INTEGER
One per annotation. Owns a branch + chat thread.
MESSAGE
id TEXT PK
agent_id TEXT → AGENT
role TEXT (user|assistant)
data TEXT (JSON)
created_at INTEGER
Chat turns within an agent. Same pattern as existing.
PART
id TEXT PK
message_id TEXT → MESSAGE
agent_id TEXT (denorm)
data TEXT (JSON)
created_at INTEGER
Message components. Kept as-is.
VARIATION
id TEXT PK
agent_id TEXT → AGENT
annotation_id TEXT → ANNOTATION
label TEXT
rationale TEXT
files TEXT (JSON — Sandpack bundle)
status TEXT (pending|approved|dismissed)
position_x REAL
position_y REAL
created_at INTEGER
Agent-generated prototype variation. Approving one updates the main prototype.
CHECKPOINT
id TEXT PK
feature_id TEXT → FEATURE
parent_id TEXT → CHECKPOINT
variation_id TEXT → VARIATION
label TEXT
files TEXT (JSON — full Sandpack)
canvas_snapshot TEXT (JSON)
created_at INTEGER
Sandpack snapshot on approval. Supports restore/fork/compare.
CONTEXT_DOC
id TEXT PK
scope TEXT (global|product|feature)
scope_id TEXT
type TEXT (prd|research|guideline|...)
name TEXT
content TEXT
is_rule BOOLEAN
created_at INTEGER
updated_at INTEGER
Files tab content. Rules go in context window, rest in RAG.
ACCOUNT
(kept as-is)
id, provider_id, provider
access_token, refresh_token
metadata, expires_at
OAuth for Figma + other MCPs.
MCP_CONFIG
id TEXT PK
product_id TEXT → PRODUCT
name TEXT
transport TEXT
command TEXT
env TEXT (JSON)
enabled BOOLEAN
priority INTEGER
Per-product MCP server configs with fallback priority.

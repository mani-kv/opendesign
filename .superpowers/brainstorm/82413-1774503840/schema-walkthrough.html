Schema Stress Test: Walking Through Your Workflow

Where does every piece of data land? What's missing?

Step 1: User opens OpenDesign, creates a Product

Data Created
ProductTable row:
  id: "a1b2c3" (git root hash)
  name: "Acme Dashboard"
  directory: "/Users/me/acme"
  git_root: "a1b2c3"
✅ Schema handles this
ProductTable maps 1:1 to a git repo. ID from root commit hash (same as old ProjectTable).

Step 2: Connect Figma, import design system

Data Created
AccountTable: OAuth token for Figma

DesignSystemTable row:
  name: "Acme Brand v2"
  figma_file_key: "abc123"
  tokens: { colors, spacing, type }
  components: [Button, Card, ...]
  last_synced_at: 1711417200

ProductDesignSystemTable:
  product_id → design_system_id
✅ Schema handles this
DesignSystem is independent of Product (can be shared).
Join table links them.
A Figma file with multiple team libraries → multiple DesignSystem rows.

Step 3: Create a Feature, paste Figma URL

Data Created
FeatureTable row:
  name: "Onboarding Flow"
  branch: "feature/onboarding"
  status: "active"
  figma_url: "figma.com/design/..."
  canvas_state: {
    viewport: { x, y, zoom },
    nodes: [RasterImageNode]
  }

❓ Where does the Figma node tree go?
❓ Where does the hit-map go?
❓ Where does the raster image binary go?
⚠️ GAP FOUND
Missing: Figma import data storage.

When we paste a URL, we get:
1. Raster image (PNG) — needs file storage, not DB
2. Node tree (JSON) — needed for hit-map / bounding boxes
3. Component references — which DS components are used where

None of these have a home in the current schema.

Fix: Add figma_node_tree and figma_raster_url to FeatureTable. Or create a FigmaImportTable.

Step 4: Base prototype generation

Data Created
AgentTable row (system agent):
  feature_id: "feat_1"
  annotation_id: NULL (no annotation)
  title: "Base prototype"
  status: "working"

Agent generates Sandpack code...

❓ Where does the "current prototype"
   Sandpack code live?
⚠️ GAP FOUND
Missing: Current prototype files.

The "live prototype" on the canvas is a Sandpack running code. That code lives... where?

Checkpoints store snapshots, but the current running prototype code needs a home.

Fix: Add prototype_files (JSON Sandpack bundle) to FeatureTable. This is the "current state" that gets updated on each approval and snapshotted into checkpoints.

Step 5: Select component, annotate, spawn agent

Data Created
AnnotationTable row:
  feature_id: "feat_1"
  component_node_id: "1234:5678"
  component_name: "CardCarousel"
  prompt: "Explore variations..."
  ds_slider: 0.3

AgentTable row:
  feature_id: "feat_1"
  annotation_id: "ann_1"
  branch: "agent/carousel-v1"
  status: "working"

✅ Schema handles this
Annotation captures the full context of what the user asked.
Agent is 1:1 with annotation.
Agent chat thread: Messages + Parts under the Agent.

DS slider value persists on the annotation, so the same component can be re-annotated with different settings.

Step 6: Agent generates variations

Data Created
4x VariationTable rows:
  agent_id: "agent_1"
  annotation_id: "ann_1"
  label: "Stacked overlap"
  rationale: "Uses depth..."
  files: { "App.tsx": "...", ... }
  status: "pending"
  position_x/y: (near annotation)
✅ Schema handles this
Each variation has its own Sandpack file bundle.
All start as "pending".
Position fields let them render near the annotation on canvas.

Note: Variation files are PARTIAL — only the section the agent changed. The full prototype is assembled by merging variation files with the current prototype_files.

Step 7: Approve variation → checkpoint

Data Changed
VariationTable update:
  status: "pending" → "approved"

FeatureTable update:
  prototype_files: merged with variation

CheckpointTable row:
  feature_id: "feat_1"
  parent_id: "cp_1" (previous)
  variation_id: "var_2"
  label: "v3 · Carousel → full-bleed"
  files: { full Sandpack snapshot }
  canvas_snapshot: { current canvas }
✅ Schema handles this (with fix)
Approval flow works:
1. Variation → "approved"
2. Feature.prototype_files updated
3. Checkpoint created with full snapshot
4. Other variations stay "pending" (dimmed in UI)

Restore = load checkpoint.files into Feature.prototype_files
Fork = new checkpoint with parent_id
Compare = diff two checkpoint.files

Gaps Found — Proposed Fixes

Gap 1: Prototype Files
The "current running prototype" (Sandpack code) has no home.

Fix: Add prototype_files TEXT (JSON) to FeatureTable.
Gap 2: Figma Node Tree
The imported Figma node tree (for hit-map / bounding boxes) has no home.

Fix: Add figma_node_tree TEXT (JSON) to FeatureTable.
Gap 3: Raster Image
Raster PNG from Figma needs file storage (too large for DB).

Fix: Store on disk at .opendesign/raster/{feature_id}.png. Add figma_raster_path to FeatureTable.

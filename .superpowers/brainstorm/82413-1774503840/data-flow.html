Key Data Flows

1. Import Flow
User pastes Figma URL
→ Parse fileKey + nodeId
→ Figma MCP: get_image, get_file_data,
  get_library_components, get_variables
→ Build component hit-map from node tree
→ AI agent generates base Sandpack code
→ Canvas renders: Sandpack prototype +
  raster reference + invisible hit regions
2. Exploration Flow
User selects component + writes prompt
→ Agent receives: component metadata,
  current code, DS at slider level,
  enrichments, files context
→ Agent generates N variation bundles
→ Each renders as Sandpack iframe on canvas
→ User approves one
→ Code swaps in main prototype
→ Auto-checkpoint (Sandpack snapshot)
3. Checkpoint Flow
Each checkpoint stores:
  - Sandpack file bundle (full prototype)
  - Metadata (label, timestamp, agent, component)
  - Parent checkpoint ID (for fork history)

Restore: load checkpoint's Sandpack files
Fork: create new branch from checkpoint
Compare: side-by-side Sandpack renders
4. Design System Flow
Figma MCP: get_library_components
→ Component catalog with variants
→ Stored in design system registry

Figma MCP: get_variables
→ Token map (colors, spacing, type)
→ tokensToStylesheet() → CSS vars
→ Injected into all Sandpack instances

DS slider position → agent system prompt:
  0%: "Use ONLY these components/tokens"
  50%: "Prefer DS, deviate with rationale"
  100%: "Explore freely, any pattern"

What Gets Killed

  • opendesign-figma-mcp — replaced by Figma's official MCP server
  • figma-write.txt agent prompt — no write-back to Figma for MVP
  • figma-ws.ts WebSocket server — no local plugin bridge needed
  • Rust/WASM canvas as primary surface — moves to visual diff overlay (P2)
  • canvas-bridge.ts — replaced by HTML canvas
  • SVG agent-sandbox canvas — replaced by HTML canvas with Sandpack
  • design.txt agent prompt — replaced by variation generation prompt

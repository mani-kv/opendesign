# Database Schema v2 — Full Re-architecture

## Overview

Clean re-architecture of the database to match the agentic prototyping studio direction. Drops TUI, upstream OpenCode compatibility, workspace/console/share systems.

**Branch:** `opendesign-v2`
**Data loss:** Accepted (nothing worth preserving).
**Migration strategy:** Drop all tables, create new ones. No migration scripts.

---

## Storage Architecture

Not everything belongs in the database. Each type of data has a natural home:

| Data | Storage | Why |
|------|---------|-----|
| Metadata & relationships | **SQLite (Drizzle)** | Product/Feature/Agent status, canvas positions, UI state |
| Prototype code | **Git** (files on feature/agent branches) | Versioning, diffing, merging — that's what git does |
| Checkpoints | **Git commits** (on feature branch) | Restore = checkout, Compare = diff, Fork = branch |
| Raster images | **File system** (`.opendesign/assets/`) | Binary files, not DB material |
| Figma node tree | **File system** (`.opendesign/figma-tree.json` on feature branch) | Versioned with the feature, used for hit-map |
| Design system config | **File system** (`.opendesign/design-system.json` + `tokens.css` on main) | Shared across branches via git inheritance |
| Canvas state (board layout) | **SQLite** (JSON column on FeatureTable) | Changes frequently (pan/zoom/drag), needs instant load |
| MCP config | **JSON files** (`opencode.json`) | Already works, no change needed |
| Context docs / RAG | **Vector DB or mem0** (deferred) | Semantic search needs embeddings, not SQLite |
| Agent memory | **mem0.ai or similar** (deferred) | Shared memory between agents is a specialized problem |

## Git Structure

The Product is a mono repo. Features and agents work on branches. Code lives on disk, not in the DB.

```
product-repo/  (main branch)
├── .opendesign/
│   ├── design-system.json          # synced tokens + components
│   ├── tokens.css                  # generated CSS vars (--od-*)
│   └── assets/                     # raster images, shared assets
├── src/                            # prototype source code (base)
│   ├── App.tsx
│   ├── components/
│   └── tokens.css
└── package.json

feature/onboarding  (branch off main)
├── .opendesign/
│   ├── figma-tree.json             # imported Figma node tree for hit-map
│   └── assets/
│       └── frame-onboarding.png    # raster reference image
├── src/                            # current prototype code (HEAD = current state)
└── [git commits = checkpoints]

agent/carousel-v1  (branch off feature/onboarding)
├── src/                            # agent's working code
└── .opendesign/variations/         # generated variation outputs
    ├── var-1/src/App.tsx
    ├── var-2/src/App.tsx
    ├── var-3/src/App.tsx
    └── var-4/src/App.tsx
```

**Key operations:**
- **Approve variation** → merge variation files into feature branch → commit = checkpoint
- **Restore checkpoint** → `git checkout <commit>` on feature branch
- **Fork from checkpoint** → `git branch feature/onboarding-v2 <commit>`
- **Compare checkpoints** → `git diff <commit1> <commit2>`
- **Complete feature** → merge feature branch into main

## Database Schema (11 tables)

The DB stores only **metadata, relationships, and canvas state**. No code, no assets, no searchable content.

### Naming Conventions
- Table names: `PascalCase` (Drizzle convention)
- Column names: `snake_case`
- JSON columns: `text({ mode: "json" }).$type<T>()`
- Timestamps: Spread `...Timestamps` (time_created, time_updated)
- Foreign keys: Always `onDelete: "cascade"` unless noted
- IDs: Text, generated via `Identifier` utility

### 1. ProductTable (replaces ProjectTable)

```typescript
// packages/opencode/src/product/product.sql.ts
export const ProductTable = sqliteTable("product", {

  directory: text().notNull(),       // absolute path to mono repo root
```

### 4. FeatureTable (NEW)

```typescript
// packages/opencode/src/feature/feature.sql.ts
export const FeatureTable = sqliteTable("feature", {
  id: text().primaryKey(),
  product_id: text().notNull().references(() => ProductTable.id, { onDelete: "cascade" }),
  name: text().notNull(),            // "Onboarding Flow"
  branch: text().notNull(),          // git branch: "feature/onboarding"
  status: text().notNull().$type<"active" | "completed" | "archived">().default("active"),
  figma_url: text(),                 // source Figma URL
  canvas_state: text({ mode: "json" }).$type<CanvasState>(),  // full board state (see below)
  ...Timestamps,
}, (table) => [
  index("feature_product_idx").on(table.product_id),
])
```

**canvas_state** is the Miro/Mural-style board document:

```typescript
interface CanvasState {
  viewport: { x: number; y: number; zoom: number }
  nodes: {
    [id: string]: {
      type: "raster" | "prototype" | "annotation" | "variation"
      x: number
      y: number
      width: number
      height: number
      visible?: boolean
      dimmed?: boolean
      collapsed?: boolean
      entityId?: string  // links to annotation/variation in DB
    }
  }
  edges: {
    source: string
    target: string
    type: "annotation-to-variation" | "flow"
  }[]
}
```

All spatial/visual data lives here. Entity tables store content/status only, not positions.

### 6. AgentTable (replaces SessionTable)

```typescript
// packages/opencode/src/agent/agent.sql.ts
export const AgentTable = sqliteTable("agent", {
  id: text().primaryKey(),
  feature_id: text().notNull().references(() => FeatureTable.id, { onDelete: "cascade" }),
  annotation_id: text().references(() => AnnotationTable.id, { onDelete: "set null" }),
```

## Entity Relationships

```

PRODUCT (1) → (N) FEATURE
PRODUCT (1) → (1) PERMISSION

FEATURE (1) → (N) ANNOTATION
FEATURE (1) → (N) CHECKPOINT

ANNOTATION (1) → (1) AGENT
ANNOTATION (1) → (N) VARIATION (via agent)

AGENT (1) → (N) MESSAGE → (N) PART
AGENT (1) → (N) VARIATION

```

## What Does NOT Live in the DB

| Data | Where | Access Pattern |
|------|-------|----------------|
| Prototype source code | Git (feature branch `src/`) | Read files from branch HEAD for Sandpack |
| Variation code | Git (agent branch `.opendesign/variations/`) | Read files from `branch_path` for Sandpack preview |
| Checkpoint snapshots | Git (commits on feature branch) | `git show <git_ref>:src/App.tsx` |
| Raster images | File system (`.opendesign/assets/`) | Served as static files |
| Figma node tree | File system (`.opendesign/figma-tree.json`) | Read on feature load for hit-map |
| Design system config | File system (`.opendesign/design-system.json`) | Read on product load |
| Token CSS | File system (`.opendesign/tokens.css`) | Injected into Sandpack instances |
| MCP config | JSON files (`opencode.json`) | Read by MCP loader |
| Context docs / RAG | Vector DB / mem0 (P2) | Semantic search by agents |
| Agent memory | mem0.ai (P2) | Cross-agent shared memory |
